# wpr-ai-digest

Digest emails from one pipeline, selected by `python digest.py [edition]`. Cadence: the four research editions alternate by ISO-week parity (`weeks` in `EDITIONS`) — **even weeks:** industry (Mon) + project digest (Fri); **odd weeks:** tools (Wed) + skills (Thu) — with a 14-day search window; the Ledger Brief (Tue) and AI Field Notes (Sat) are weekly, grants monthly. Both triggers dispatch every week; `main()` exits free on an off-week.
- `wpr` (default) — Fridays, to Rowan: new AI tools/features from the past ~10 days with applications tied to specific WPR builds. `context.md`, `seen.json`, `.github/workflows/digest.yml`.
- `industry` — Mondays, to Rowan + editor: AI in local journalism generally (newsroom tools, case studies, grants, platform shifts, ethics), written for an editorial reader. `context-industry.md`, `seen-industry.json`, `.github/workflows/digest-industry.yml`.
- `tools` — Wednesdays, to Rowan + editor: new and trending AI tools and plug-ins anyone can use same-day (apps, WordPress plugins, extensions, no-code automation), general reader. `context-tools.md`, `seen-tools.json`, `.github/workflows/digest-tools.yml`.
- `ledgers` — Tuesdays, to Rowan + editor: assignment memo diffed from WPR's own tracker JSONs (`LEDGER_SOURCES` in digest.py) — Python fetches and diffs against `ledgers-state.json`, Claude writes the brief (no web search, ~$0.15, $1 cap). Skips the send when nothing changed. `context-ledgers.md`, `seen-ledgers.json`, `.github/workflows/digest-ledgers.yml`.
- `skills` — Thursdays, to Rowan: new and trending Claude skills / Claude Code plugins, ranked by fit to WPR's stack, excluding everything in `skills-installed.json` (prompt exclusion + `drop_installed()` hard filter). **Re-run `python skills_inventory.py` and commit after installing or removing skills** — it scans `~/.claude/skills`, plugins, and Anthropic's bundled skills. `context-skills.md`, `seen-skills.json`, `.github/workflows/digest-skills.yml`.
- `ideas` — **weekly**, Saturdays, to Rowan: AI Field Notes — techniques, workflows, prompts, and money-making ideas from practitioners, sorted into three buckets (fits our work / could pay / fascinating). `gather_feeds()` pulls candidates for free — Reddit top-of-week RSS one subreddit at a time (JSON is closed; the RSS rate limit is ~a few requests/minute, so a run spends several minutes waiting; combined multi-sub feeds were rejected because big subs crowd out small ones) and the Substack public API (`/api/v1/posts`, with likes/comments). Plus Hacker News via the free Algolia API (`hn_candidates()`): Show HN and Ask/Tell HN with low points bars (builders and practitioners), ordinary stories only above 100 points (they're mostly launch news), all AI-filtered by `AI_TERMS`. Claude can't read Reddit, so it gets a client-side tool, `reddit_comments` (handled in `research()`'s `tool_use` branch): it asks for a candidate thread's top 8 comments and the script fetches them (`reddit_comments()`, candidate URLs only, `REDDIT_COMMENT_CALLS` = 8 per run). The ideas edition allows 20 rounds (`rounds`) for the extra tool turns. **Feedback loop** (`feedback` key in `EDITIONS`, ideas only so far): each pick carries More/Less-like-this links (`feedback_link()`) that open a pre-filled GitHub issue; the next run's `collect_feedback()` folds the owner's open vote issues into `feedback-ideas.md` (newest 40 kept), the prompt includes that file as taste, and `close_feedback()` closes the issues after a successful send (best-effort, never fails the run). **Only issues opened by the repo owner are accepted** — the repo is public, so anyone else's issue would be a prompt-injection channel. Rowan can also edit the file's Standing preferences directly. The workflow needs `issues: write` and `GITHUB_TOKEN`. Reddit blocks Anthropic's crawler: listing reddit.com in `allowed_domains` makes the API 400, and Reddit threads can't be fetched — the RSS text is the thread (top 3 per sub get ~1,200 chars). Substack blocks GitHub's datacenter IPs on `*.substack.com` API calls, so `_substack_rss()` falls back to the RSS feed. The model reads Substack posts and the pages Reddit threads link to (10 fetches at 6k tokens, 6 searches limited to Substack). $4 cap. `context-ideas.md`, `seen-ideas.json`, `.github/workflows/digest-ideas.yml`; sources in `IDEA_SUBREDDITS` / `IDEA_SUBSTACKS`.
- `leads` — **weekly**, Mondays, to Rowan: Sponsor Leads — prospects for sponsorships/ads from the Coming Soon tracker (permits, alcohol licenses, commercial sales). `research_leads()` diffs by signal id against `leads-state.json`, `lead_tier()` scores HOT (imminent signal + a second *kind* of signal) / WARM / WATCH, one Claude call writes it up (no web tools, cents per run, $1 cap). Skips quiet weeks. Guardrails in `context-leads.md`: coverage is never for sale; business-level only. `seen-leads.json`, `.github/workflows/digest-leads.yml`.
- `grants` — 1st of each month, to Rowan + editor: currently-open grants/fellowships for small nonprofit newsrooms, deadline-sorted, deadlines confirmed via fetch. `context-grants.md`, `seen-grants.json`, `.github/workflows/digest-grants.yml`.

Each edition's context file owns its entire selection framing, including the "How to rank and pitch" section the code prompt defers to.

`hub.py` regenerates `docs/index.html` — a static status hub (per edition: schedule, recipients, last sent, item history) derived entirely from repo state; each workflow reruns it after a send. New editions following the `digest-{key}.yml` convention appear automatically.

## How it works
- `digest.py` — three functions, one path: `research()` (Claude + server-side web search/fetch → JSON), `render()` (inline-styled HTML in WPR colors), `send()` (Gmail SMTP). `main()` wires them and appends covered items to `seen.json`.
- `context.md` — everything the model knows about WPR: stack, project list, what counts as a good find. **Edit this, not the prompt in code**, when a new project ships or priorities change.
- Recipients live in `DIGEST_TO` in the workflow env, comma-separated; `send()` puts the list in the To header and `send_message` delivers to each.
- `seen.json` — names/urls already surfaced; fed back into the prompt so weeks don't repeat. Committed by the workflow after each send.
- **On-time sends come from Rowan's PC**: a Windows scheduled task ("WPR Digest Trigger", 6:47am daily) runs `local-run.ps1`, which refreshes `skills-installed.json` (commits if changed) and dispatches the day's edition via `gh workflow run`. GitHub's 11:47 UTC cron is only a fallback — it fires 3–5 hours late — and `main()` skips a second real send on the same day (seen file's last date == today). Log: `%LOCALAPPDATA%\wpr-ai-digest\local-run.log`. All five share a `concurrency` group so same-day sends queue instead of racing on the `seen`/hub commit. Each has `dry_run` (research + render, preview as artifact, no send, no commit) and `force` (send even on an off-week or if already sent today — manual tests only) dispatch inputs.
- `min_items` per edition (default 3) — grants and ledgers use 1, since a thin month/week should still send rather than fail. `validate_items()` rejects a malformed answer before anything is rendered or sent.
- Ledgers: one unreachable tracker is reported in the log and in the email masthead, its previous hashes carried forward; only all-sources-down fails the run.
- Research loop: the `_20260209` web tools run in a server-side code-exec container — a `pause_turn` continuation must pass `container=<id>` back or the API 400s. Tool `max_uses` is per request, so each round's budget is recomputed from what remains (`tools_for`).
- `requirements.txt` pins `anthropic>=1,<2` — a major SDK bump must be deliberate, never picked up by a cron.

## Local
`python -m pip install -r requirements.txt; $env:ANTHROPIC_API_KEY="..."; python digest.py --dry-run` → writes `digest-preview.html`, sends nothing, doesn't touch `seen.json`.

## Principles
No fallbacks, fail loud. Missing env var, bad JSON, wrong item count, or an unexpected stop_reason all raise. If a run fails, the workflow shows red and no email goes out — that's the signal.

Cost: the research loop sums real usage (cache writes/reads, output, search fees) across every pause_turn round and raises past the edition's `max_cost` — $6 for the four biweekly research editions (a 14-day window plus continuation rounds runs $2–3; a run that dies at the cap after 45 minutes is the worst outcome), $3 grants, $1 ledgers. Runs use the full search/fetch budget every time (25/16), so item count is budget-bound — raise those before loosening the quality bar. Pricing constants sit next to `MODEL` in digest.py — update both together. Prompt caching keeps continuation rounds at ~10% input price; `FETCH_CONTENT_TOKENS` caps how much of a fetched page enters context.
